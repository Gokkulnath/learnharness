# LearnHarness on Termux (Android)

Run LearnHarness as a supervised production service on an Android phone with
[Termux](https://termux.dev). This is the quick path; the patch-by-patch
reference lives in [`patches/README.md`](patches/README.md).

> **Note:** the `patches/` directory in this branch is the historical bundle used
> to produce these changes. They are already applied here — do **not** apply the
> patches again on this branch.

## What you get

- Next.js production server on `0.0.0.0:3000`, supervised by runit
  (`termux-services`) and restarted automatically on crash or reboot-session
  start.
- The compact phone layout (`0.8×` density at ≤ 927 px), safe-area-aware drawer
  and long-questionnaire fit.
- A production-only PWA shell: manifest, icons, and a pass-through service
  worker (nothing is cached, so a rebuilt `.next` is never masked by a stale
  shell).

Verified on: Android/arm64, Termux, Node 26.x / npm 11.x, Next 16.3.2.

## Requirements

- Termux from **F-Droid** or the **GitHub** releases. The Play Store build
  applies a stricter sandbox and is not supported for this workflow.
- Packages: `nodejs` (26.x), `git`, `termux-services`, `termux-tools`.
- ~2 GB free space for `node_modules` and `.next`.
- Termux battery usage set to **Unrestricted** (keeps the wake lock effective).

```sh
pkg install nodejs git termux-services termux-tools
```

## Quick start

```sh
git clone https://github.com/amosblomqvist/learnharness
cd learnharness
sh scripts/termux/install.sh
```

The installer checks prerequisites, installs dependencies (skipping the useless
Electron binary), builds with webpack, installs the runit unit, starts it, and
verifies `http://127.0.0.1:3000`.

## Everyday commands

```sh
sh scripts/termux/build.sh             # rebuild + restart after code changes
sh scripts/termux/service.sh status    # sv status + local health check
sh scripts/termux/service.sh logs      # tail the service log
sh scripts/termux/service.sh restart
sh scripts/termux/service.sh stop
sh scripts/termux/service.sh remove    # stop and uninstall the runit unit
```

Environment overrides for both scripts:

| Variable | Default | Meaning |
|---|---|---|
| `LH_HOST` | `0.0.0.0` | Bind address for `next start` |
| `LH_PORT` | `3000` | Port |
| `LH_SERVICE_NAME` | `learnharness` | runit service name |
| `SVDIR` / `LOGDIR` | `$PREFIX/var/{service,log}` | runit directories |

Example on another port:

```sh
LH_PORT=8080 sh scripts/termux/install.sh
```

The service log is `$PREFIX/var/log/sv/$LH_SERVICE_NAME/current`.

## Build notes

- **Turbopack does not run on Android/arm64.** Always build with webpack:
  `npm run build -- --webpack`.
- `NODE_OPTIONS=--max-old-space-size=3072` avoids `next build` OOM kills on
  devices with limited free RAM.
- `ELECTRON_SKIP_BINARY_DOWNLOAD=1` skips a ~100 MB download that cannot run on
  Android.
- `next-env.d.ts` is regenerated by `next build`; do not commit those diffs.
- Stop the service before building — `next build` rewrites `.next` under a
  running server. `build.sh` does this for you.
- If a rebuild leaves the old `next-server` holding port 3000
  (`sv status` shows `got TERM`), force it once with
  `SVDIR=$PREFIX/var/service sv kill learnharness`.

## Phone / PWA

Open `http://localhost:3000` **on the phone itself** and use “Install app” /
“Add to Home screen”. A service worker needs a secure context: `localhost`
qualifies, a plain LAN IP does not. The LAN URL still works for normal
browsing; it is just not installable without HTTPS.

## Security

The service has **no authentication**. Keep it on a trusted LAN. For remote
access put an authenticated proxy in front of it (Tailscale, Cloudflare Access,
or nginx/Caddy with basic auth) instead of exposing port 3000 directly.

## Rollback

```sh
sh scripts/termux/service.sh remove          # uninstall the service
git apply -R --binary patches/0003-mobile-pwa-shell.patch
git apply -R patches/0001-core-barrel-browser-safe.patch
```

(`0002` only describes the runit unit, which `service.sh remove` deletes.)

## Known limitations

- No Chrome/Chromium on the build device: the compact drawer, `0.8×` density,
  long-questionnaire fit and PWA install still need a real-device visual check.
- The file watcher in `next dev` is not supported on Android; production mode is
  unaffected.
- Android 12+ may kill background child processes of Termux
  (phantom-process killer). If the server disappears while the phone is idle,
  keep Termux unrestricted and/or disable the phantom-process killer over adb
  (`settings put global settings_enable_monitor_phantom_procs false`).
